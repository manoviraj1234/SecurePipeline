# SecurePipeline – FastAPI Backend & SQLite Database

This is the backend service for the **SecurePipeline** DevSecOps platform. It ingests, validates, persists, and serves real security scan reports generated by CI/CD pipelines (GitHub Actions) and local security scans.

## 🗄️ Database Schema

The backend uses a local, lightweight SQLite database (`securepipeline.db`) with three core relational tables:

1. **`scans`**:
   - Primary key: `id` (int)
   - Unique identifier: `report_id` (str)
   - Gate decision: `gate_decision` (`PASS`, `BLOCK`, `INCOMPLETE`)
   - Security score: `security_score` (int, 0–100 or null if incomplete)
   - Severity counts: `critical_count`, `high_count`, `medium_count`, `low_count`, `info_count`
   - Scanner metadata: `scanner_status` (JSON), `sbom_total_packages` (int)
   - Relationships: One-to-many with `findings` and `scanner_executions`.

2. **`findings`**:
   - Primary key: `id` (int), foreign key: `scan_id`
   - Identifier: `finding_id` (e.g., CVE, rule ID)
   - Deduplication: `fingerprint` (SHA-256 hash)
   - Severity: `severity` (`CRITICAL`, `HIGH`, `MEDIUM`, `LOW`, `INFO`)
   - Details: `title`, `description`, `file`, `line`, `package`, `installed_version`, `fixed_version`, `remediation`, `references`.

3. **`scanner_executions`**:
   - Primary key: `id` (int), foreign key: `scan_id`
   - Tool name: `scanner_name` (`semgrep`, `gitleaks`, `syft`, `trivy_fs`, `trivy_image`)
   - Status: `status` (`success`, `failed`, `not_installed`, `skipped`)
   - Diagnostics: `error_message`, `findings_count`.

## 🚀 Setup & Execution Guide (Windows PowerShell)

### 1. Navigate to Backend Directory
```powershell
cd C:\Users\venna\.gemini\antigravity\scratch\securepipeline\dashboard\backend
```

### 2. Create and Activate Virtual Environment
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. Install Dependencies
```powershell
pip install -r requirements.txt
```

### 4. Start the FastAPI Server
```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

* **API Root:** `http://127.0.0.1:8000`
* **Interactive Swagger UI:** `http://127.0.0.1:8000/docs`
* **Alternative ReDoc UI:** `http://127.0.0.1:8000/redoc`

## 📡 API Endpoints

### Health Check
* `GET /api/health` – Returns backend and database operational status.

### Scans Management
* `GET /api/scans` – Paginated scan history (query params: `skip`, `limit`, `gate_decision`).
* `GET /api/scans/{scan_id}` – Full detail of a specific scan with findings.
* `POST /api/scans/ingest` – Ingests raw JSON security report.
* `POST /api/scans/ingest-file?file_path=reports/security_report.json` – Helper endpoint to ingest a report directly from local disk.

### Findings Exploration
* `GET /api/findings` – Paginated list of vulnerabilities (query params: `severity`, `scanner`, `search`, `scan_id`).
* `GET /api/findings/{finding_id}` – Detail of a specific vulnerability finding.

### Dashboard & Analytics
* `GET /api/dashboard/summary` – High-level KPI summary (total scans, pass/block/incomplete counts, latest score).
* `GET /api/dashboard/severity-distribution` – Critical, High, Medium, Low, Info distribution.
* `GET /api/dashboard/scanner-status` – Scanner health from latest scan.
* `GET /api/dashboard/scan-history` – Recent scans for time-series charts.

## 📥 Ingesting Real Security Reports

You can ingest the report generated by the CI/CD pipeline (`reports/security_report.json`) using cURL or PowerShell:

```powershell
# Using PowerShell Invoke-RestMethod
Invoke-RestMethod -Uri "http://127.0.0.1:8000/api/scans/ingest-file?file_path=../../reports/security_report.json" -Method Post
```

Or via cURL:
```bash
curl -X POST "http://127.0.0.1:8000/api/scans/ingest" \
     -H "Content-Type: application/json" \
     --data-binary "@../../reports/security_report.json"
```
